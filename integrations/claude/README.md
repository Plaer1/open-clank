# Open Clank Claude Code Integration

This directory contains the Claude Code skill bundle for Open Clank.

Use the setup commands generated by **Settings → Integrations** for the
installation's current address and token. Use `OPEN_CLANK_URL` and `OPEN_CLANK_API_TOKEN` for scoped access. Use verified HTTPS for remote access and keep tokens private.
These integration credentials are separate from app login, model subscription
login and mailbox authorization.

## User Flow

1. Open Open Clank Settings > Integrations.
2. Add a Claude Agent.
3. Copy the full setup commands shown after the generated token.
4. Toggle the tools Claude is allowed to use.
5. Configure the terminal Claude Code session:

```bash
export OPEN_CLANK_URL=http://127.0.0.1:7777
export OPEN_CLANK_API_TOKEN=ody_generated_token
mkdir -p ~/.claude
curl -fsSL -H "Authorization: Bearer $OPEN_CLANK_API_TOKEN" "$OPEN_CLANK_URL/api/claude/plugin.zip" -o /tmp/openclank-claude-skill.zip
python3 -m zipfile -e /tmp/openclank-claude-skill.zip ~/.claude/
```

Claude Code auto-loads anything under `~/.claude/skills/`, so the `openclank` skill is
available in any session that has `OPEN_CLANK_URL` and `OPEN_CLANK_API_TOKEN` in its
environment.

## What's in the bundle

- `skills/openclank/SKILL.md` — the skill definition Claude Code reads.
- `skills/openclank/scripts/openclank_api.py` — small helper that calls the scoped
  `/api/codex/*` endpoints (these are the canonical scope-gated agent API; the
  `codex` path is historic and shared by all agent integrations).

## Scope enforcement

The token is scope-gated. Every tool surface is checked server-side in Open Clank,
so even if Claude tries to call a forbidden endpoint, it gets `403` until the
user enables the matching toggle in Settings > Integrations > Claude Agent.
