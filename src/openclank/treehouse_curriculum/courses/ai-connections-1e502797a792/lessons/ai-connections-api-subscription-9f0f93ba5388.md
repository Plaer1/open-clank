# API access and subscriptions

- An API is a defined interface through which software requests an operation and receives a structured response. A finished app supplies a user interface and its own orchestration.
- Caller software → request/API → inference/model → response. The harness controls context, tools and continuation around those calls.

All four offers below are fictional supplied contracts.

| Offer | Identity and scope | Authorization and billing |
| --- | --- | --- |
| Studio UI | user U in finished app | Monthly app plan excludes generic API use in these terms; app owns harness |
| Lab API | project P, project-scoped token | Authorized programmable endpoint; separately metered paper rates; client owns harness |
| Supported Native | user U in named supported client | Explicit subscription sign-in for this client only; arbitrary wrappers unspecified |
| Local server | machine M, separately licensed downloaded weights | Server stopped; no provider usage fee under this contract; hardware/electricity cost unknown |

Choose Studio for the finished-app need, Lab for a presently authorized own integration and Supported Native for its named client. Local is only a potential alternative after compatibility, license, resources and a running interface are established.

An unrelated mailbox credential grants none of these model permissions. Unknown wrapper entitlement stays unknown until its actual supported terms are checked; neither universal permission nor universal prohibition follows.
