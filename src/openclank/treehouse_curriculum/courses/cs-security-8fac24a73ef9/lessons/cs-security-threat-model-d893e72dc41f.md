# Model a failure before testing

- Identify what matters, who can act, entry points, and where trust changes.
- For a document service: asset=private content; threat=another account reads it; boundary=request→server; control=resource authorization.
- Include residual risk and a check that would challenge the control. A diagram is a reasoning aid, not proof.

**Try:** Add an availability threat to the service, one mitigation, and one limitation.
