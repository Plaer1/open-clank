# Measure growth and assumptions

- Choose input size n and count relevant work. A scan touches at most n items; a nested all-pairs loop touches n² pairs.
- O is an eventual upper bound, Ω a lower bound, Θ both. Specify worst, best, expected, or amortized case separately.
- Time and space differ. Constant factors, allocation, and cache behavior still matter for real inputs.

**Try:** For a loop that visits every ordered pair of n items, state time growth. If it stores only one running total, state extra-space growth.
