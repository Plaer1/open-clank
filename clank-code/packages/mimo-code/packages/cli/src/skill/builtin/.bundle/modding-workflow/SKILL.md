# Modding workflow

Start with the user's selected target and intended behavior. Prefer a supported route before a hook or rewrite; distinguish what is verified from what is missing. Check the capabilities and permissions actually available for this task. Do not initiate an unrequested whole-machine scan or tool installation, or assume an engine name or source availability proves compatibility.

For route selection, a behavior oracle, faithful-port parity, or a bridge between runtimes, read [intake and bridge](references/intake-and-bridge.md). For an experiment, failed or partial outcome, or retaining and comparing evidence, read [evidence and iteration](references/evidence-and-iteration.md). For a selected save set, recovery, or publication preparation, read [save and sharing](references/save-and-sharing.md). Read only the reference needed for the current work.

Use existing authorized tools and evidence owners. An instruction here grants no access or publication permission. Report unavailable capabilities and unresolved claims; do not infer successful execution from a plan, course, or tool's presence.
