# Evidence and iteration

For a small experiment retain the question and hypothesis, selected authorized resource identity and revision, content hash when actually measured, tool/version and operation, observation, interpretation, unresolved gap and next decision. Preserve the actual failed, partial or unavailable result alongside successful observations. Do not replace an unknown with a guessed result or equate source availability with completion or runtime parity.

Use existing owners: Files and History/Lore retain their resource and operation receipts; Graph owns its evidence views. Memery retains its existing capture, review and admission policy; this skill grants no new admission or sharing authority. Do not create a parallel ledger or automatically publish knowledge. History exact-output paging needs the exact eligible message-part revision and hash and is not a generic file receipt.

A verified C1/C2 provider dossier retains a bounded provider interpretation and its source/result identity, not independently proven runtime behavior. A provider-virtual address is not a file offset. An explicitly approved analysis snapshot can retain selected normalized results and hierarchical file/folder checksums independently of later source access. A later comparison requires fresh Files authority and can report incomplete, inaccessible or unknown coverage. Do not infer unchanged bytes from an unavailable comparison.

Keep the smallest useful milestone and proportionate check visible. Describe whether evidence is observed, inferred or unresolved, and obtain the task's actual authorization before sharing or publishing. Optional lessons can teach these methods; their presence does not prove a workflow ran.
