03 / BORROW THE GOOD BITS

Improve what is already here.

01 / MODEL INTENT

Make the binding dependable.

Preserve MiMo’s custom requested/effective model records. Validate the final provider/model/reasoning binding after profiles, groups, and machine-managed configuration. Reject unsupported selections.

Useful donor: Codex’s durable binding and model-selection tests. Explicit user choice remains the authority.

02 / WORKER CONTINUITY

A message is not always a wake-up.

Add queue-only delivery separately from follow-up. Preserve task owner, identity, decisions, and outstanding work through interruption. Show role, deliverable, and status.

Useful donors: Codex message/trigger semantics; Kimi reconstruction, task settlement, and mailbox ideas.

03 / EXECUTION VISIBILITY

Give running work a handle.

Use existing PTYs for inspect/write/cancel and reconnect. Record whether a process is live, finished, cancelled, or unrecoverable after daemon death.

Useful donors: Codex unified exec; Kimi background-task and terminal lifecycle tests. MiMo already supplies core PTY plumbing.

04 / HISTORY-BACKED UI

Make the worker room legible.

Stable tool/turn/interaction IDs, pending questions, stale-steer rejection, and history resync. Keep native extension data when normalizing events.

Useful donors: Kimi vis/KAP projections and Codex item/request structure. Keep original media separate from previews and model transforms.

Also take relevant upstream provider, retry, nested-call, compaction, and title fixes. A second JavaScript engine or a whole new desktop shell is not needed to acquire capabilities MiMo already has.

05 / THE SWITCHBOARD

Run both. Be precise about “swap.”

A viable proposal is an explicit harness profile per session, behind the existing supervisor facade. Each profile pins a customized build, adapter, configuration, capabilities, and native state home. Current dispatch still depends on MiMo’s ACP bridge, and the Rust adapter is health-only: this needs implementation.

Feasible after adapter work

Two engines, separate sessions.

Session A stays on MiMo while a new session B explicitly uses Codex or Kimi. Separate processes/state, stable native IDs, and workspace coordination keep them from trampling each other. MiMo can retain non-agent managed operations while the alternate handles selected agent conversations.

This illustration does not launch or change a harness. Model selection remains a separate user choice.

Useful continuation with explicit loss

Handoff at a known checkpoint.

Stop new actions, finish or cancel tools with known outcomes, settle worker/interaction state, and save decisions, visible transcript, artifacts, model intent, and outstanding work. Create a fresh native session in the selected engine; retain the old binding for inspection and return.

This transfers task context. Private checkpoints, hidden reasoning, caches, and live process handles do not become portable.

Not established

An active turn cannot simply change engines.

Running tools, pending approvals, child contexts, native IDs, and provider state have engine-specific ownership. None of these audits established live migration. Finish or interrupt, reconcile outcomes, then perform a paused handoff.

Matching JSON or ACP labels are not proof of portable execution state.

Suggested binding shape:

owner + workspace + canonical session/revision → harness profile/build + adapter/schema/config + native session/actor + runtime generation + explicit provider/model/reasoning intent

Preserve typed events and native extensions. MiMo SSE needs history resync; PTY cursor replay is separate. Codex request IDs and Kimi prompt_id duplicate rejection do not guarantee exactly-once effects. Keep process confinement at the OS boundary. Full adapter design (private historical evidence).

EXPOSURE NOTES

Tower is experimental and initially exposes only Init/Status/Teardown in the default root profile. Fork and select_tools are gated; media needs model support. Goals/cron enforce main-agent-only execution. TaskOutput reads status/output; WaitFor does waiting. Bash and a human PTY terminal are different surfaces.

DYNAMIC NAMES ARE NOT FINITE

Configured MCP servers add mcp__server__tool names and, conditionally, authentication tools. SDK/client user tools supply arbitrary names. Plugins can contribute MCP/skills/hooks; these are not hidden fixed native tools. No native browser/computer-use/image-generation tool appeared among the 40.

07 / AFTER YOU PONDER

A small path to useful proof.

  1. Protect the baseline.Preserve working bytes and build identity. Map custom changes by behavior; choose the upstream pin explicitly.
  2. Fix continuity first.Model binding, queue versus follow-up, cold worker reuse, visible process outcomes, and identified interactions.
  3. Refresh in slices.Reapply custom contracts, regenerate SDK, and verify provider/owner/file/memory behavior with focused suites.
  4. Try one alternate.Codex app-server if required Responses providers fit; Kimi ACP if provider translation dominates. Explicit selection only.
  5. Prove recovery.Fake-provider tests, cancellation/reconnect, stale steering, empty-worker wake, revocation, and owner lifecycle.
  6. Then judge the pivot.Measure reliability, maintenance, and whole supervisor/worker cost. Attempt paused handoff only after both adapters pass.

Saved candidate plan ↗ (private historical evidence) · Concrete acceptance experiments ↗ (private historical evidence)

What could overturn MiMo-first? A refresh that repeatedly breaks essential hooks, permanent invasive continuity patches, incompatible upstream terms, or an alternate that passes the same app/provider tests with materially lower maintenance and measured failure rates. Those outcomes have not been established by this research.
