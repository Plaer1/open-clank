MI MO · POST UPDATEV02 / 2026

The recommendation: preserve customized MiMo, then improve continuity, provider capabilities and media flow. Actors, code mode, PTYs, persistence and provider plumbing already exist.

“Post-update” is the target baseline. This audit did not perform the update. Mozart—your Brave fork—is future architectural context; browser integration has no implementation milestones here.

01 / PRESERVE

The useful foundation

Owner/account lifecycle, files, memory, canonical history, hex rules, managed operations and MiMo’s native runtime.

02 / COMPLETE

The missing behavior

Exact worker model inheritance, restart recovery, durable process handles, qualified search and image/capture/OCR delivery.

03 / BORROW

The useful details

Kimi’s task and interaction state, diagnostic UI, media provenance and lifecycle cases. Codex’s capture-and-inspect workflow.

Model choice stays yours. Workers inherit the parent unless an applicable user instruction selects another. An explicitly cheaper worker remains on that choice through follow-up and resume. No automatic upgrades, downgrades or model routing. This also applies to model-backed search helpers; Qwen’s auxiliary default must not be imported silently.

Official authentication · Image inputs

CAPTURE → INSPECT → VERIFY

The Codex pattern

Capture comes from browser/OS tooling; image viewing inspects the result. Reuse existing fixtures and tool paths to save, inspect and recapture relevant UI state as part of the task.

No periodic background screen observation is proposed.

ORIGINALS + DERIVATIVES

One artifact lineage

Retain original images, model-sized versions, crops, OCR and user corrections. Link them with dimensions, scale, source and task identity through existing files/history.

OCR

Useful structured text

Extend current vision/document processing with reading order, regions and original-pixel coordinates. Measure known-text fixtures; keep uncertainty visible. Select a local OCR adapter only if concrete gaps justify it.

06 / FUTURES

Five bounded slices

  1. Baseline: identify the actual refresh and preserve custom contracts.
  2. Continuity: worker models, follow-up, process handles, questions and recovery.
  3. Search: qualified providers, direct results, Antigravity, image retrieval and extraction.
  4. Media: original image delivery, task-triggered capture and structured OCR.
  5. Donors and conformance: selective Kimi reuse and a combined workflow demonstration.

After the baseline, continuity and search can progress independently; media coordinates shared contracts with them. Implementation belongs to assigned workers in a later phase.

07 / EVIDENCE
